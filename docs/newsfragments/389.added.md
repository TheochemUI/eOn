Vendored vesin updates to 0.6.0 with three local extensions carried as
upstream candidates: a CPU implementation of the declared-but-missing
``VesinBruteForce`` algorithm (nearest-image MIC pair search), lazy
thread-pool worker spawn (serial consumers stop paying
``hardware_concurrency()`` thread creations per process), and a fused pair
visitation API (``vesin_neighbors_visit`` plus the header-only
``vesin_visit.hpp``).

The upstream vesin Fortran interface (``fortran/src/{cdef,vesin}.f90``) is
vendored at the same version and built as ``vesin_fortran`` under
``with_fortran``. All seven Fortran potentials consume vesin-backed
neighbour candidates: SW, EDIP, and Lenosky build their per-atom lists
through ``use vesin`` directly (the EDIP/Lenosky cell/ghost scaffolding is
gone); Aluminum, CuH2, and FeHe enumerate candidates through CSR helper
modules while keeping their own MIC and sign conventions; Tersoff trades
its O(N^3) sweeps for per-atom lists. SW's silent MAXNEI overflow and
FeHe's 800-neighbour gather ceiling are hard errors now.
